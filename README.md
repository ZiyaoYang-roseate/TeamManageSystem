# NBA 球队管理系统

这是一个面向篮球联赛的管理与比赛模拟系统，也是一个软件工程课程设计项目。系统把球队备赛、比赛计分、赛后复盘和阵容管理连在一起，通过三种角色分工完成。项目使用 Flask、Jinja、MySQL 和 Chart.js，附带可在本机生成的模拟数据，便于在另一台电脑上演示，不需要复制原电脑的数据库。

## 项目特点

- **一场比赛串起三个角色。** 球队管理层在赛前分析里发布出勤和首发；双方首发齐全才可开赛；记分员录入事件，同步更新比分、技术统计、逐回合记录和投篮分布；联赛管理员在比赛管理页跟踪进度并核查完赛。
- **赛前、赛后有不同的可见范围。** 管理层只看本队视角的赛前分析，赛后可以回看全联盟已完赛比赛的复盘。报告可回查到技术统计、投篮区域或具体回合，方便教练组验证建议。
- **从阵容需要出发做签约和交易。** 对比球队短板、同位置球员、候选人的技术特点和薪资空间，将历史数据转成具体的使用建议。例如，引进助攻能力强的后卫，可以让他带领第二阵容发起挡拆；可在后续比赛观察助攻、失误和队友获得空位的机会。方案也会说明轮换位置、薪资影响和数据样本限制。
- **球员数据与主页统一。** 得分、篮板、助攻、抢断、盖帽和三分命中分别提供降序排行榜，支持场均与总计。点击姓名进入球员主页；“全部球员”也包含暂无出场记录的球员。球队主页展示本队完整现有名单；球员主页集中展示生涯效力球队、实际出场日期范围和赛季表现。
- **补强方案有可解释的评级。** 手动签约和交易分析、智能辅助方案及交易加签约组合，均按本队情况显示 S、A、B、C、D、E 等级与分数。赛场补强占 60%、轮换适配占 25%、薪资成本占 15%，并列出历史表现、未来职责、位置变化和预算依据。S≥90、A≥80、B≥65、C≥50、D≥35，其余为 E；样本不足、位置空缺和规则阻碍可限制评级。评级用于比较未来补强价值，不代表胜率或加盟后的统计预测。
- **AI 可选，操作有明确的确认流程。** 可接入 DeepSeek 来整理比赛建议和球队决策，未配置模型也能用规则生成报告和方案。签约、发送交易申请、接受交易都要由相应管理层确认，服务端会重新校验。

## 首次在本机安装：数据库、账号和启动

下面的流程适用于另一台 Windows 电脑，也适用于第一次在本机安装。命令兼容 **Windows PowerShell 5.1 和 PowerShell 7**。请在同一个 PowerShell 窗口依次执行，命令前的说明和输出示例不需要输入。

需要先安装：

- **Python 3.12**：安装时勾选加入 PATH；用 `py -3.12 --version` 检查。
- **MySQL Server 8.0**：需要实际安装数据库服务，只有 Workbench 客户端不能运行数据库。安装时记住 `root` 密码，确认 MySQL 服务正在运行。
- **Git**：用于克隆代码；也可以下载仓库 ZIP 并解压。

本系统有两套独立的凭据：**MySQL 的账号密码用于程序连接数据库；联赛管理员、管理层和记分员的账号密码用于网页登录。** 下文新建的网页演示账号密码是 `123456`，它不是 MySQL 的 `root` 密码。

### 1. 下载项目并安装 Python 依赖

任选一个仓库下载。两条克隆命令只执行一条：

```powershell
# GitHub
git clone https://github.com/ZiyaoYang-roseate/TeamManageSystem.git

# 或 Gitee
git clone https://gitee.com/roseate/team-manage-system.git TeamManageSystem
```

进入项目目录并安装依赖。如果下载的是 ZIP，先在解压后的项目目录打开 PowerShell，跳过 `cd` 这一行。

```powershell
cd TeamManageSystem
py -3.12 -m venv .venv-windows
$python = ".venv-windows/Scripts/python.exe"
& $python -m pip install -r requirements.txt
```

后续使用 `& $python` 运行命令，确保安装依赖和运行网站使用同一个 Python 环境。

### 2. 连接本机 MySQL

在同一个窗口设置连接信息。以下使用本机安装的 MySQL 管理账号 `root`；如果安装时使用了其他账号或端口，请按实际情况替换。

```powershell
$env:MYSQL_HOST = "127.0.0.1"
$env:MYSQL_PORT = "3306"
$env:MYSQL_USER = "root"
$mysqlCredential = Read-Host "请输入本机 MySQL 的 root 密码" -AsSecureString
$env:MYSQL_PASSWORD = [System.Net.NetworkCredential]::new("", $mysqlCredential).Password
$env:MYSQL_DATABASE = "nba_management_demo"
```

- `MYSQL_HOST` 是数据库所在电脑；本机使用 `127.0.0.1`。
- `MYSQL_PORT` 是 MySQL 服务端口，默认 `3306`。
- `MYSQL_USER`、`MYSQL_PASSWORD` 是安装 MySQL 时创建的数据库账号密码。
- `MYSQL_DATABASE` 是本项目的数据存放位置。下面的演示初始化要求库名以 `_demo` 结尾，脚本可以自动创建它，无需手工导入 SQL。

可以在 MySQL Workbench 用相同的主机、端口、用户名和密码测试连接。若服务未启动，在 Windows「服务」中启动对应的 MySQL 服务。项目直接读取上述环境变量，**不会自动加载 `.env` 文件**。这些变量只在当前 PowerShell 窗口内有效，关闭窗口后下次需重新设置。

### 3. 初始化本地数据库

第一次安装时运行：

```powershell
& $python init_db.py --reset-demo
```

该命令自动创建目标数据库、创建业务表、写入模拟数据并执行迁移。出现「演示库重建完成」和「已对账完赛: 135」表示成功。全新演示库包含 30 支球队、270 场赛程、135 场已完赛的技术统计与逐回合，以及合同、自由球员和选秀候选资料；完赛比分与相关事件会自动核对。

**这个命令会重建目标演示库并清除原有比赛进度和网页登录账号。仅首次安装或明确需要重置演示进度时运行。** 日常打开网站不需要再次执行。

### 4. 初始化三个角色及所有球队的账号密码

数据库初始化完成后运行：

```powershell
& $python init_demo_accounts.py --create-missing
```

在刚创建的 30 队演示库中，此命令创建 **32 个网页登录账号**，并在终端逐条列出角色、球队、用户名和初始化结果：

- 联赛管理员：用户名 `league_admin`，密码 `123456`，登录时选择「联赛管理员」。
- 记分员：用户名 `scorekeeper`，密码 `123456`，登录时选择「记分员登录」。
- 球队管理层：每支球队一个账号，用户名为 `gm_` 加球队英文缩写的小写，密码 `123456`，登录时选择「管理层登录」。
- 例如湖人是 `gm_lal`，开拓者是 `gm_por`，凯尔特人是 `gm_bos`。完整名单以命令输出为准。

每个管理层账号绑定自己的球队。**重复执行只补建缺失账号，不重置已有账号的密码，也不替换已有球队账号。** 如果输出为「保留」，请使用该账号原来的密码，不能假定也是 `123456`。没有球队数据时只会创建联赛管理员和记分员，新增球队后可再次运行以补齐管理账号。

`123456` 是本地课程演示的初始密码。此初始化脚本仅允许连接本机、且库名以 `_demo` 结尾的数据库，数据库保存的是密码哈希。若使用非演示业务库，或需要自行指定用户名和密码，请使用手动管理命令：

```powershell
# 创建联赛管理员或记分员，随后按提示输入并确认密码
& $python manage_users.py my_admin --role league_admin
& $python manage_users.py my_scorer --role scorekeeper

# 为球队 ID 为 1 的球队创建管理层；该球队不能已经绑定其他管理账号
& $python manage_users.py my_gm --role management --team 1

# 忘记密码时重置单个账号，随后按提示输入新密码
& $python manage_users.py gm_lal --reset-password
```

手动管理命令要求密码至少 12 个字符；它与本地演示初始化的固定密码规则不同。球队 ID 可在目标数据库查询 `SELECT id, abbreviation, name FROM teams ORDER BY id;`。

### 5. 启动网站并登录

仍在前面配置过数据库连接的 PowerShell 窗口执行：

```powershell
$env:FLASK_SECRET_KEY = & $python -c "import secrets; print(secrets.token_hex(32))"
.\active.ps1 -Python $python
```

看到服务监听地址后，浏览器打开 [http://127.0.0.1:5000](http://127.0.0.1:5000)。先选择账号对应角色，再输入第四步初始化的用户名和密码。可分别使用不同浏览器或隐私窗口同时演示三个角色，避免同一浏览器的登录会话互相覆盖。

`FLASK_SECRET_KEY` 用于网页登录会话，与 MySQL 密码和网页登录密码都不同；换一个密钥后需要重新登录。`active.ps1` 只启动 Web 应用，不执行数据库重建。服务窗口需保持打开，按 `Ctrl+C` 停止。当前地址仅供运行服务的电脑访问，在其他电脑测试时可以按本文自建数据库并启动。

### 6. 下次快速启动，保留已有数据

如果原 PowerShell 窗口仍在，直接执行 `.\active.ps1 -Python $python` 即可。如果已经关闭窗口，在项目目录打开新窗口，重新设置连接和会话密钥后启动：

```powershell
$python = ".venv-windows/Scripts/python.exe"
$env:MYSQL_HOST = "127.0.0.1"
$env:MYSQL_PORT = "3306"
$env:MYSQL_USER = "root"
$mysqlCredential = Read-Host "请输入本机 MySQL 的 root 密码" -AsSecureString
$env:MYSQL_PASSWORD = [System.Net.NetworkCredential]::new("", $mysqlCredential).Password
$env:MYSQL_DATABASE = "nba_management_demo"
$env:FLASK_SECRET_KEY = & $python -c "import secrets; print(secrets.token_hex(32))"
.\active.ps1 -Python $python
```

不要重跑 `init_db.py --reset-demo`，这样会保留现有账号、比赛、合同和分析记录。更新代码后如需升级表结构，使用文末「升级已有业务数据库」的流程。

### 可选：使用没有模拟业务数据的空库

设置第二步的连接信息，将库名改成一个新的名称，然后执行：

```powershell
$env:MYSQL_DATABASE = "nba_management_local"
& $python migrate_db.py --create-database
& $python manage_users.py league_admin --role league_admin
```

这里仅创建结构，**不会生成球队、赛程或默认账号密码**。按提示设置管理员密码，启动后由管理员维护球队和球员，再按球队 ID 创建管理账号，另行创建记分员。需要完整的课程演示流程时优先使用前面的模拟数据方案。

## 球队管理层：备赛、复盘和管理阵容

从登录页选「管理层登录」，然后点侧栏「球队」，直接进入本队主页。可以查看近期与下一场比赛、赛季表现、球员名单以及薪资。球队账号绑定一支球队，只有该队的资料、出勤、首发和私有阵容操作可由此账号修改。

1. **备赛并提交首发。** 从本队主页或「赛事中心」进入本队比赛，打开「赛前分析」。待开赛、进行中或完赛后都可以查看；分析以比赛当日之前的完赛数据为基准，结合对手出手热点、重点球员、本场伤病和轮休公告，给出对位、防守和轮换建议。临时出勤未公布时按页面提示核实。在赛前分析里发布本队出勤，生成 AI 分析可获得推荐首发五人，结合位置、此前比赛表现和缺阵情况核对后，点“填入首发勾选”；也可自行勾选五名可出场球员，点「提交本队首发五人」。开赛前可修改，记分员确认开赛后由记分员记录场上换人。
2. **赛后复盘。** 在「赛事中心」打开任一已完赛比赛的「赛后复盘」。查看关键时段、技术统计和出手区域，点引用回看比赛证据。教练组可以把建议转成训练任务，例如复查连续丢后场篮板的回合，再安排卡位训练，并在下一场跟踪二次进攻失分。
3. **自由市场签约。** 在「自由市场」加入或选择候选人，填写首年薪资、年限、涨幅、选项等条款。先点「保存报价」，核对逐年薪资后点「按已保存报价签约」。也可直接点「智能辅助」里的「生成签约方案」，无需先选球员。最多返回三套方案，核对持球、投射或篮板特点与当前轮换是否互补，再点「应用并确认签约」。合同保留确认的条款，目前未提供执行或放弃合同选项的操作。
4. **发起或审批交易。** 在「发起交易」手动选择双方球员，先校验再「发送交易方案」；也可用「智能辅助」里的「生成交易方案」搜索双方各 1 至 3 名球员的组合，推荐最多三套方案（包括二换一、一换二和多人互换），查看预计角色、未来比赛中的使用方式、样本与风险和双方薪资影响，点「应用并发送申请」。对方管理层在「交易收发记录」接受或拒绝，发起方可取消待处理申请。只有对方接受且再次校验通过后，球员归属和合同才会变更。

在侧栏打开「薪资与阵容规划」查看本队未来三季预算、合同到期、末年选项及位置覆盖。点「生成组合方案」可比较最多三套交易加签约的补强方案。应用后会先发送交易申请，对方接受后，发起方在「发出的交易」复核并确认自由市场签约。单独的签约或交易也可以在原页面预览逐年预算。

打开「选秀准备」后可查看候选人所属的外部学校或青年队、赛事赛季、技术特点、适应风险和试训问题。点“AI 推荐候选人”无需预先勾选，系统结合本队短板、到期合同和候选人的大学等外部比赛资料，推荐最多三名优先考察对象，并说明预期用法、风险和试训重点；可加入本队选秀板。也可勾选 2 至 3 人按本队需求并排比较。加入选秀板时可指定位置或排到末位，其他候选会跟随顺延。演示库的 2026 届外部赛事实例均为虚构。上述两个工作区仅向本队管理层开放。

## 记分员：检查首发并录完整场比赛

从登录页选「记分员登录」，进入「计分员赛程日历」。**当前比赛日**取自系统中的赛程进度。电脑今天的日期可能和演示赛程不同，切换浏览的日期也不会自动改变可计分日期。赛事中心和记分员日历都按当前比赛日优先、待开始其次、已完赛最后排列，完赛按日期从近到远展示。当前比赛处理完后，由联赛管理员推进比赛日。记分员侧栏和球员主页不显示球员对比入口。

1. 在日历打开当前比赛日的比赛，核对双方提交的首发。名单不齐时请对应球队补交；齐全后点「开始比赛」，首发直接载入计分面板。升级前已开打但无首发确认的比赛可在双方补交后点「确认首发并继续」。
2. 在比赛页更新节次和时钟，为场上球员记录投篮、罚球、篮板、助攻、失误等。录入两分或三分出手时在球场图上选点；换人后更新场上五人。核对比分、技术统计和逐回合列表是否同步。
3. 误录时，可在比赛进行中对最近一条支持更正的有效事件点「撤销误录」，填入原因再重新录入。系统会回退关联比分或统计，逐回合仍保留原记录及更正原因。
4. 比分分出胜负后即可确认完赛。后续没有新增统计时，可以在任意节次按已录入比分结束，实际节次、时钟和完赛说明会保留。仍需继续记录的比赛按节次推进，末节打平可进入加时。结束后通知球队管理层查看复盘。

## 联赛管理员：跟踪全联盟并处理待办

从登录页选「联赛管理员」，进入「联赛比赛管理」。先处理进行中的比赛，再查看当前比赛日首发准备进度，结束后开放下一比赛日。每个入口都进入同一场比赛的处理页。

1. **推进比赛日与跟进首发。** 下一比赛日之前的比赛都结束后，从运营台推进日期。从首发待办查看双方已提交的名单，联系对应球队补齐。
2. **确认完赛。** 在「进行中」点击「处理比赛」，后续没有新增统计时，可以按当前领先比分直接完赛，并填写可选说明。已完赛比赛按实际记录截止时间展示，时钟未归零也可正常完赛。处理页统一提供技术统计、逐回合和赛后复盘入口；查看后可以返回比赛处理页。
3. **维护联赛资料。** 在球队页和“球员数据 → 全部球员 → 球员主页”维护全联盟档案，在运营台查看球队管理账号覆盖情况。需要创建或重置账号时，使用前面的 `manage_users.py` 命令。管理员可发布各队共用的选秀候选资料，各队私有排名与笔记由球队管理层维护。

比赛进行期间可以提交交易申请。涉及正在参赛球队的成交、签约、裁员和归档在完赛后才能执行。联赛管理员可以归档球员或球队。历史比赛、技术统计和合同继续可查。归档球队会取消尚未开赛的赛程和待审批交易，并停用该队管理层的操作入口。

## 建议的演示顺序

1. 用联赛管理员登录，在运营台找当前比赛日一场待开赛比赛。全新演示库可选 **2025–26 赛季，2025 年 12 月 4 日，开拓者主场对湖人**，正好对应上面创建的两个球队账号。如果演示进度已推进，在运营台确认当前比赛日，为参赛双方创建各自的管理账号。
2. 用一方球队管理账号进入本队主页，展示赛前分析、出勤和首发；双方提交后，切到记分员，展示首发自动载入、录入和撤销误录。演示更新时钟和计分，比分分出胜负后可按当前已录入数据完赛，或继续按节次记录。
3. 切回管理员核查比赛，用球队管理账号查看赛后复盘并回查证据。再打开另一场已完赛比赛，验证跨球队可查看赛后复盘。
4. 用球队管理账号演示两处「智能辅助」。讲解一条建议对未来轮换的作用和薪资成本；如果演示交易的成交环节，为接收方准备管理账号，在「交易收发记录」中接受。

## 可选：接入 DeepSeek

可直接用本地数据和规则完成演示。如果有 DeepSeek API Key，在**启动应用的同一个 PowerShell 窗口**设置以下变量，已运行时先停掉再启动：

```powershell
$env:NBA_AI_PROVIDER = "deepseek"
$env:NBA_AI_MODEL = "deepseek-flash"
$env:DEEPSEEK_API_KEY = [System.Net.NetworkCredential]::new("", (Read-Host "DeepSeek API Key" -AsSecureString)).Password
.\active.ps1 -Python $python
```

重新打开分析页面，点击「生成」或「重试模型生成」。模型从已有证据中整理重点和建议，页面显示的统计值来自系统快照。模型不可用时可以继续使用规则结果。报告保存来源和历史版本；私有签约、交易及选秀的模型整理使用本队需要、候选样本、阵容和预算约束及允许的行动选项。如果改用 OpenAI，设置 `NBA_AI_PROVIDER=openai`、`OPENAI_API_KEY` 及支持 Responses API 结构化输出的 `NBA_AI_MODEL`。已经配置本机加密启动器的用户也可用 [configure_deepseek.ps1](configure_deepseek.ps1) 保存 DeepSeek 配置。API Key 和真实密码请保存在本机。

## 升级已有业务数据库

1. 备份业务库，停止应用写入。将 `MYSQL_DATABASE` 设置为要升级的业务库名，并设置有结构迁移权限的 MySQL 账号。
2. 执行 `& $python migrate_db.py`，确认成功后换回日常运行账号并启动。迁移记录存放在 `schema_migrations`，已有业务数据会保留。旧版 `*_migration.sql` 用于查看历史。
3. 如果运行账号按表授权，检查新分析表 `game_analysis_snapshots`、`game_analysis_reports` 的查询、插入及更新权限，`game_player_availability`、`game_starters` 的查询、插入、更新及删除权限，以及 `play_by_play`、`shot_attempts` 的更新权限。
4. 迁移版本 7 新增选秀候选池、本队选秀板和联赛完赛核查表。按表授权的运行账号需能读写这些表，选秀板还需要删除权限。已有库可由管理员发布候选人。
5. 迁移版本 8 为球员和球队增加归档字段。应用沿用原表读写授权。对于旧版初始化生成的模拟数据，可先运行 `& $python repair_demo_history.py` 预览能识别和核实的旧比赛。备份后使用 `--apply --expected-count <预览数量>` 对账。修复从原逐回合和投篮记录还原得分、助攻与投篮统计，不重置数据库。原有报告保存在历史中，点「按最新数据生成」查看新报告。
6. 旧账号可用 `--reset-password` 更新不符合当前要求的演示密码。历史招募记录缺少球队归属时不会出现在球队看板，核实归属后由数据库管理员补录；缺少赛季的旧报价需要在选定赛季重新保存后才能签约。

## 常见问题与测试

- **初始化报 `Access denied`：** 确认填写的是本机 MySQL 账号和密码，且该账号有权建库、建表。受限的日常运行账号可能无法创建新库。
- **登录不上或提示请求凭据无效：** 先确认所选登录角色、账号是否创建在当前配置的库，以及应用连接的库名是否与建账号时一致。如果刚重启并更换了会话密钥，请刷新登录页后重新提交；仍失败可用隐私窗口重试。
- **记分员无法开赛：** 检查比赛是否属于当前比赛日、双方首发是否已提交、当前是否有冲突的开赛状态，以计分页面提示为准。
- **智能辅助返回少于三套方案：** 系统会剔除不符合阵容、薪资或交易规则的组合；球员比赛样本不足时，页面会降低结论确定性。工资帽、交易配平和演示数据用于课程场景，请按系统展示的简化规则使用。

自动化回归测试无需连接 MySQL。在安装完依赖后运行：

```powershell
& $python -B -m unittest discover -s tests -v
```

三角色的数据库联调测试需要一套刚初始化的独立演示库。将 `MYSQL_DATABASE` 指向专用的 `_demo` 库，再执行：

```powershell
& $python -B init_db.py --reset-demo
$env:NBA_RUN_MYSQL_TESTS = "1"
& $python -B -m unittest discover -s tests -p test_mysql_delivery.py -v
Remove-Item Env:NBA_RUN_MYSQL_TESTS
```

测试会在该演示库写入账号、比赛事件、交易和归档记录。GitHub Actions 使用单独的 MySQL 服务执行同一用例。
