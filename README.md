# NBA 球队管理系统

这是一个面向篮球联赛的管理与比赛模拟系统，也是一个软件工程课程设计项目。系统把球队备赛、比赛计分、赛后复盘和阵容管理连在一起，通过三种角色分工完成。项目使用 Flask、Jinja、MySQL 和 Chart.js，附带可在本机生成的模拟数据，便于在另一台电脑上演示，不需要复制原电脑的数据库。

## 项目特点

- **一场比赛串起三个角色。** 球队管理层在赛前分析里发布出勤和首发；双方首发齐全才可开赛；记分员录入事件，同步更新比分、技术统计、逐回合记录和投篮分布；联赛管理员在运营台跟踪进度并核查完赛。
- **赛前、赛后有不同的可见范围。** 管理层只看本队视角的赛前分析，赛后可以回看全联盟已完赛比赛的复盘。报告可回查到技术统计、投篮区域或具体回合，方便教练组验证建议。
- **从阵容需要出发做签约和交易。** 对比球队短板、同位置球员、候选人的技术特点和薪资空间，将历史数据转成具体的使用建议。例如，引进助攻能力强的后卫，可以让他带领第二阵容发起挡拆；可在后续比赛观察助攻、失误和队友获得空位的机会。方案也会说明轮换位置、薪资影响和数据样本限制。
- **AI 可选，操作有明确的确认流程。** 可接入 DeepSeek 来整理比赛建议和球队决策，未配置模型也能用规则生成报告和方案。签约、发送交易申请、接受交易都要由相应管理层确认，服务端会重新校验。

## 在另一台电脑上初始化并运行

以下以 Windows 和 PowerShell 7 为例。先安装 Git、Python 3.12 和 MySQL Server 8.0，确认 MySQL 服务已启动，记住安装时为 MySQL 管理账号设置的密码。**MySQL 密码用于连接数据库，网页登录密码在第三步单独创建。**

### 1. 下载代码并安装依赖

任选一个仓库克隆。如果是下载 ZIP，解压后直接在项目目录打开 PowerShell，执行安装依赖的部分。

```powershell
# GitHub
git clone https://github.com/ZiyaoYang-roseate/TeamManageSystem.git

# 或者从 Gitee 下载（与上一条二选一）
git clone https://gitee.com/roseate/team-manage-system.git TeamManageSystem

cd TeamManageSystem
py -3.12 -m venv .venv-windows
$python = ".venv-windows/Scripts/python.exe"
& $python -m pip install -r requirements.txt
```

### 2. 创建本机演示数据库

在同一窗口运行以下命令，密码输入时不会明文显示。默认 MySQL 管理账号为 `root`；如果你用其他有权在目标库建表、改表和写入数据的账号，请替换 `MYSQL_USER`。

```powershell
$env:MYSQL_HOST = "127.0.0.1"
$env:MYSQL_PORT = "3306"
$env:MYSQL_USER = "root"
$env:MYSQL_PASSWORD = Read-Host "本机 MySQL 密码" -MaskInput
$env:MYSQL_DATABASE = "nba_management_demo"

& $python init_db.py --reset-demo
```

出现「演示库重建完成」和数据数量即表示成功。脚本会自动创建数据库、建表、写入 30 支球队和模拟球员、赛程、历史比赛数据，再应用迁移。**仅首次在空库上执行，或确实要清空演示进度时执行。** 重跑会清除目标演示库中的项目表及其中的网页登录账号。脚本要求库名以 `_demo` 结尾。希望从空库开始录入时，可以设置一个新的库名，再运行 `& $python migrate_db.py --create-database`，之后创建联赛管理员账号，由管理员维护球队和球员档案。

### 3. 创建三个角色的网页登录账号

初始化只生成演示业务数据。下面创建四个账号，分别覆盖三种角色和两支球队。密码按提示输入两次，至少 12 个字符。用户名可改成自己的，演示库没有默认网页登录密码。

```powershell
& $python manage_users.py league_admin --role league_admin
& $python manage_users.py demo_gm_lal --role management --team 1
& $python manage_users.py demo_gm_por --role management --team 27
& $python manage_users.py demo_scorer --role scorekeeper
```

新建的演示库中，`1` 是湖人，`27` 是开拓者。要给其他球队创建账号，可在 MySQL Workbench 选中目标库后查询 `SELECT id, abbreviation, name FROM teams ORDER BY id;`，再把球队 ID 填到 `--team`。每支球队关联一个管理账号。忘记密码时，用 `& $python manage_users.py demo_scorer --reset-password` 重置对应账号。

### 4. 启动并登录

```powershell
$env:FLASK_SECRET_KEY = & $python -c "import secrets; print(secrets.token_hex(32))"
.\active.ps1 -Python $python
```

浏览器打开 [http://127.0.0.1:5000](http://127.0.0.1:5000)，先选择匹配账号的角色，再输入用户名和密码。此地址仅供运行服务的电脑访问；想在另一台电脑上测试，就在那台电脑上重复以上步骤。按 `Ctrl+C` 停止。下次启动时重新设置数据库连接或复用原窗口，再执行启动命令，无需重建或创建账号。日常可沿用同一个会话密钥；换密钥后需要重新登录。长期运行请使用仅有业务库所需读写权限的 MySQL 账号，安装用的管理员账号留给初始化和迁移。

## 球队管理层：备赛、复盘和管理阵容

从登录页选「管理层登录」，然后点侧栏「球队」，直接进入本队主页。可以查看近期与下一场比赛、赛季表现、球员名单以及薪资。球队账号绑定一支球队，只有该队的资料、出勤、首发和私有阵容操作可由此账号修改。

1. **备赛并提交首发。** 从本队主页或「赛事中心」进入本队比赛，打开「赛前分析」。待开赛、进行中或完赛后都可以查看；分析以比赛当日之前的完赛数据为基准，结合对手出手热点、重点球员、本场伤病和轮休公告，给出对位、防守和轮换建议。临时出勤未公布时按页面提示核实。在赛前分析里发布本队出勤，勾选五名可出场球员，点「提交本队首发五人」。开赛前可修改，记分员确认开赛后由记分员记录场上换人。
2. **赛后复盘。** 在「赛事中心」打开任一已完赛比赛的「赛后复盘」。查看关键时段、技术统计和出手区域，点引用回看比赛证据。教练组可以把建议转成训练任务，例如复查连续丢后场篮板的回合，再安排卡位训练，并在下一场跟踪二次进攻失分。
3. **自由市场签约。** 在「自由市场」加入或选择候选人，填写首年薪资、年限、涨幅、选项等条款。先点「保存报价」，核对逐年薪资后点「按已保存报价签约」。也可直接点「智能辅助」里的「生成签约方案」，无需先选球员。最多返回三套方案，核对持球、投射或篮板特点与当前轮换是否互补，再点「应用并确认签约」。合同保留确认的条款，目前未提供执行或放弃合同选项的操作。
4. **发起或审批交易。** 在「发起交易」手动选择双方球员，先校验再「发送交易方案」；也可用「智能辅助」里的「生成交易方案」直接搜索最多三套一换一方案，查看预计角色、未来比赛中的使用方式、样本与风险和双方薪资影响，点「应用并发送申请」。对方管理层在「交易收发记录」接受或拒绝，发起方可取消待处理申请。只有对方接受且再次校验通过后，球员归属和合同才会变更。

## 记分员：检查首发并录完整场比赛

从登录页选「记分员登录」，进入「计分员赛程日历」。**当前比赛日**取自系统中的赛程进度。电脑今天的日期可能和演示赛程不同，切换浏览的日期也不会自动改变可计分日期。当前比赛处理完后，使用「推进比赛日」进入下一比赛日；日期只能向后推进，且所选日期之前的比赛都须完赛。

1. 在日历打开当前比赛日的比赛，核对双方提交的首发。名单不齐时请对应球队补交；齐全后点「开始比赛」，首发直接载入计分面板。升级前已开打但无首发确认的比赛可在双方补交后点「确认首发并继续」。
2. 在比赛页更新节次和时钟，为场上球员记录投篮、罚球、篮板、助攻、失误等。录入两分或三分出手时在球场图上选点；换人后更新场上五人。核对比分、技术统计和逐回合列表是否同步。
3. 误录时，可在比赛进行中对最近一条支持更正的有效事件点「撤销误录」，填入原因再重新录入。系统会回退关联比分或统计，逐回合仍保留原记录及更正原因。
4. 每节时钟归零后再推进下一节。第四节结束时若打平，继续五分钟加时；第四节或当前加时归零且已分胜负，才可完赛。结束后通知球队管理层查看复盘。

## 联赛管理员：跟踪全联盟并处理待办

从登录页选「联赛管理员」，进入「联赛运营台」。这里集中查看当前及下一比赛日的安排、双方首发准备进度、正在进行的比赛、待生成复盘和完赛记录异常。

1. **赛前跟进。** 从待办打开比赛并查看双方赛前分析。球队遇到操作问题时，可切换到对应视角，代为发布该队的出勤公告或首发。
2. **比赛监督。** 从运营台跟进在打的比赛，核查赛后比分、结束时钟和逐回合记录。比赛的开赛、计分和误录更正由记分员从计分入口完成。
3. **维护联赛资料。** 在球队和球员页面维护全联盟档案，在运营台查看球队管理账号覆盖情况。需要创建或重置账号时，使用前面的 `manage_users.py` 命令。管理层的自由市场报价和交易审批由对应球队处理。

## 建议的演示顺序

1. 用联赛管理员登录，在运营台找当前比赛日一场待开赛比赛。全新演示库可选 **2025–26 赛季，2025 年 12 月 4 日，开拓者主场对湖人**，正好对应上面创建的两个球队账号。如果演示进度已推进，改选当前比赛日的比赛，并给参赛方创建账号；管理员也可以代发其中一方的首发。
2. 用一方球队管理账号进入本队主页，展示赛前分析、出勤和首发；双方提交后，切到记分员，展示首发自动载入、录入和撤销误录。按顺序推进节次，第四节结束且分出胜负后完赛。
3. 切回管理员核查比赛，用球队管理账号查看赛后复盘并回查证据。再打开另一场已完赛比赛，验证跨球队可查看赛后复盘。
4. 用球队管理账号演示两处「智能辅助」。讲解一条建议对未来轮换的作用和薪资成本；如果演示交易的成交环节，为接收方准备管理账号，在「交易收发记录」中接受。

## 可选：接入 DeepSeek

可直接用本地数据和规则完成演示。如果有 DeepSeek API Key，在**启动应用的同一个 PowerShell 窗口**设置以下变量，已运行时先停掉再启动：

```powershell
$env:NBA_AI_PROVIDER = "deepseek"
$env:NBA_AI_MODEL = "deepseek-flash"
$env:DEEPSEEK_API_KEY = Read-Host "DeepSeek API Key" -MaskInput
.\active.ps1 -Python $python
```

重新打开分析页面，点击「生成」或「重试模型生成」。模型从已有证据中整理重点和建议，页面显示的统计值来自系统快照。模型不可用时可以继续使用规则结果。报告保存来源和历史版本；私有签约、交易的模型整理只使用概括后的因素和行动选项。如果改用 OpenAI，设置 `NBA_AI_PROVIDER=openai`、`OPENAI_API_KEY` 及支持 Responses API 结构化输出的 `NBA_AI_MODEL`。已经配置本机加密启动器的用户也可用 [configure_deepseek.ps1](configure_deepseek.ps1) 保存 DeepSeek 配置。API Key 和真实密码请保存在本机。

## 升级已有业务数据库

1. 备份业务库，停止应用写入。将 `MYSQL_DATABASE` 设置为要升级的业务库名，并设置有结构迁移权限的 MySQL 账号。
2. 执行 `& $python migrate_db.py`，确认成功后换回日常运行账号并启动。迁移记录存放在 `schema_migrations`，已有业务数据会保留。旧版 `*_migration.sql` 用于查看历史。
3. 如果运行账号按表授权，检查新分析表 `game_analysis_snapshots`、`game_analysis_reports` 的查询、插入及更新权限，`game_player_availability`、`game_starters` 的查询、插入、更新及删除权限，以及 `play_by_play`、`shot_attempts` 的更新权限。
4. 旧账号可用 `--reset-password` 更新不符合当前要求的演示密码。历史招募记录缺少球队归属时不会出现在球队看板，核实归属后由数据库管理员补录；缺少赛季的旧报价需要在选定赛季重新保存后才能签约。

## 常见问题与测试

- **初始化报 `Access denied`：** 确认填写的是本机 MySQL 账号和密码，且该账号有权建库、建表。受限的日常运行账号可能无法创建新库。
- **登录不上或提示请求凭据无效：** 先确认所选登录角色、账号是否创建在当前配置的库，以及应用连接的库名是否与建账号时一致。如果刚重启并更换了会话密钥，请刷新登录页后重新提交；仍失败可用隐私窗口重试。
- **记分员无法开赛：** 检查比赛是否属于当前比赛日、双方首发是否已提交、当前是否有冲突的开赛状态，以计分页面提示为准。
- **智能辅助返回少于三套方案：** 系统会剔除不符合阵容、薪资或交易规则的组合；球员比赛样本不足时，页面会降低结论确定性。工资帽、交易配平和演示数据用于课程场景，请按系统展示的简化规则使用。

自动化回归测试无需连接 MySQL。在安装完依赖后运行：

```powershell
& $python -B -m unittest discover -s tests -v
```
